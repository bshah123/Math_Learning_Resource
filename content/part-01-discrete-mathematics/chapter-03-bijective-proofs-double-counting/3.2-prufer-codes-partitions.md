Look closely at the number of labeled trees on $n$ vertices `{1, 2, ..., n}` for small values of $n$:
- $n = 1$: $1$ tree ($1^{-1} = 1$).
- $n = 2$: $1$ tree (`1-2`, $2^0 = 1$).
- $n = 3$: $3$ trees (pick which vertex is the middle of a $3$-vertex path: $3 = 3^1$).
- $n = 4$: $12$ paths plus $4$ stars $= 16 = 4^2$.

Always getting $n^{n-2}$ looks almost magical! After all, the tree shapes themselves vary wildly between paths, stars, and branched trees. How could such an uneven jumble of trees possibly have an exact count like $n^{n-2}$—the count of unconstrained sequences of length $n - 2$ from $\{1, \dots, n\}$? In 1918, Heinz Prüfer discovered a bijective "zipper" (**Prüfer codes**) that flattens every labeled tree into a unique list of $n - 2$ numbers, and unzips back uniquely.

In the second half of this lesson, we apply that same bijective mindset to **integer partitions** (ways to break a whole number $n$ into positive summands), discovering Euler's astonishing Odd = Distinct Partition Theorem via **Glaisher's bijection**.

## 1. Prüfer Codes and Cayley's Formula

> [!THEOREM]
> **Cayley's Formula & Degree-Constrained Tree Count**
> 1. There are exactly $n^{n-2}$ distinct labeled trees on the vertex set $\{1, 2, \dots, n\}$.
> 2. More precisely, given prescribed positive degrees $d_1, \dots, d_n$ summing to $2n - 2$, the number of labeled trees where vertex $i$ has degree $d_i$ equals the multinomial coefficient:
> $$\frac{(n - 2)!}{\prod_{i=1}^n (d_i - 1)!}.$$

How can a twisted tree possibly pack into a flat string of length $n - 2$ without losing information? Notice every tree with $n \ge 2$ has at least two leaves (Lesson 1.1). Instead of chopping randomly, we make one deterministic rule so both encoder and decoder agree on which leaf comes next:

> [!DEFINITION]
> **Prüfer Encoding and Decoding Algorithms**
> - **Encoding (Tree $\to$ Code of length $n - 2$)**: While more than $2$ vertices remain, locate the **leaf with the smallest label**, write down its **unique neighbor**, and delete that leaf from the tree. Stop as soon as $2$ vertices remain.
> - **Decoding (Code $(a_1, \dots, a_{n-2}) \in [n]^{n-2}$ $\to$ Tree)**: At step $i = 1, \dots, n - 2$, find the **smallest vertex label** that has *never been deleted yet* AND *does not appear anywhere in the remaining code suffix* $(a_i, \dots, a_{n-2})$. Connect that vertex to $a_i$, and mark it deleted! After all $n - 2$ steps, two unused vertices remain—connect them with the final $(n-1)$-th edge.

> [!INTUITION]
> **Why Every Vertex $v$ Appears $\deg(v) - 1$ Times in the Code**
> Think about how a vertex $v$ gets written onto the Prüfer list. It gets written down once for each incident edge attached to $v$ whose *other* endpoint is peeled off as a leaf. Does all of $v$'s edges peel away? Not quite—every vertex eventually either gets deleted itself (leaving only its **one** final edge to its surviving neighbor!), or survives to become one of the final $2$ vertices joined by **one** last edge! Either way, **every single vertex $v$ appears in the code exactly $\deg(v) - 1$ times**. That immediately proves Part 2 of Cayley's Theorem, because counting trees with degree list $(d_1, \dots, d_n)$ simply counts strings of length $n - 2$ where label $i$ occurs $d_i - 1$ times!

### Concrete Walkthrough on $n = 6$ Vertices

Take the labeled tree on `{1, 2, 3, 4, 5, 6}` with edges `1-4, 2-4, 3-5, 4-5, 5-6`. Notice vertices `1, 2, 3, 6` are leaves, while `4` and `5` both have degree $3$:
1. Smallest leaf is `1` (neighbor `4`). Record **`4`**, delete `1`.
2. Remaining leaves are `2, 3, 6`. Smallest is `2` (neighbor `4`). Record **`4`**, delete `2`.
3. Remaining leaves are `3, 4, 6` (`4` just became a leaf!). Smallest is `3` (neighbor `5`). Record **`5`**, delete `3`.
4. Remaining leaves are `4, 6`. Smallest is `4` (neighbor `5`). Record **`5`**, delete `4`.
5. Only `{5, 6}` remain ($2$ vertices!), so stop!

The resulting Prüfer code is **`[4, 4, 5, 5]`**. Sure enough, vertices `4` and `5` (degree $3$) appear $3 - 1 = 2$ times each, while the original leaves `1, 2, 3, 6` (degree $1$) appear $1 - 1 = 0$ times!

> [!EXAMPLE]
> **Degree-Constrained Counting With Prüfer Codes**
> How many labeled trees on $\{1, 2, 3, 4, 5, 6\}$ give vertex `1` degree $3$?
> By our degree rule, vertex `1` must appear $\deg(1) - 1 = 2$ times inside the length-$4$ Prüfer code, and the other $2$ slots must avoid `1` (so $5$ choices each from `{2, 3, 4, 5, 6}`). Choose the $2$ positions for `1` in $\binom{4}{2} = 6$ ways and fill the other $2$ slots in $5^2 = 25$ ways, yielding $6 \times 25 = 150$ trees (out of $6^4 = 1296$ total!).

> [!NOTE]
> **Matrix-Tree Theorem (For Non-Complete Graphs)**
> What if some edges are forbidden (not every edge of $K_n$ is allowed)? Form the **Laplacian matrix** $L = D - A$ (degrees on the diagonal, $-1$ on edges, $0$ elsewhere). **Kirchhoff's Matrix-Tree Theorem** (statement only) guarantees that the number of labeled spanning trees of *any* graph $G$ equals any $(n-1) \times (n-1)$ cofactor of $L$. As a quick formula to remember, the complete bipartite graph $K_{m,n}$ has exactly $m^{n-1} n^{m-1}$ spanning trees!

## 2. Integer Partitions: Mirror Diagrams & Glaisher's Trick

An **integer partition** of $n$ writes $n$ as a sum of positive integers where order does *not* matter (for instance, `5 = 3 + 2` is the same as `2 + 3`). We visualize any partition by stacking rows of dots from longest to shortest, called a **Ferrers diagram**.

- **Conjugation (Reflecting across the main diagonal)**: Flip a Ferrers diagram so rows become columns! Every row corresponds to a part, so the *number of rows* flips into the *size of the largest part*. Immediately, the number of partitions of $n$ into at most $k$ parts equals the number of partitions of $n$ whose every part is at most $k$.
- **Euler's Odd-vs-Distinct Partition Theorem (Glaisher's Bijection)**: Amazingly, for every $n$, the number of partitions using **only odd parts** (repeats allowed) equals the number of partitions using **all distinct parts**! Why?
  Look at each repeated odd part $k$ occurring $m_k$ times. Write the multiplicity $m_k$ in **binary** as $m_k = 2^{e_1} + 2^{e_2} + \dots$, and bundle copies of $k$ in powers of $2$: replace the $m_k$ copies of $k$ with distinct even-or-odd numbers $2^{e_1} k, 2^{e_2} k, \dots$. Because *every* positive integer splits uniquely into $(\text{power of } 2) \times (\text{odd number})$, breaking any distinct partition back apart by pulling powers of $2$ out of each part recovers the original odd parts uniquely!
*Check $n = 5$*:
- Odd parts: `5` ($1 \times 5 \to 5$), `3 + 1 + 1` ($1\cdot 3$ and $2\cdot 1 \to 3 + 2$), and `1 + 1 + 1 + 1 + 1` ($5\cdot 1 = (4+1)\cdot 1 \to 4 + 1$). Look: `{5}`, `{3, 2}`, `{4, 1}` are *all* $3$ distinct partitions of $5$!

## 3. Python Prüfer & Glaisher Verifier

Let us run both the Prüfer encode/decode round-trip and Glaisher's odd-to-distinct bijection in Python:

```python
from collections import Counter

def prufer_encode(n, edges):
    adj = {i: set() for i in range(1, n + 1)}
    for u, v in edges:
        adj[u].add(v)
        adj[v].add(u)
    code = []
    for _ in range(n - 2):
        leaf = min(v for v, nbrs in adj.items() if len(nbrs) == 1)
        nbr = next(iter(adj[leaf]))
        code.append(nbr)
        adj[nbr].remove(leaf)
        del adj[leaf]
    return code

def prufer_decode(code):
    n = len(code) + 2
    deg = Counter(code)
    used = set()
    edges = []
    for i, a in enumerate(code):
        rem = set(code[i:])
        leaf = min(v for v in range(1, n + 1) if v not in used and v not in rem)
        edges.append((leaf, a))
        used.add(leaf)
    u, v = [x for x in range(1, n + 1) if x not in used]
    edges.append((u, v))
    return edges

tree_edges = [(1, 4), (2, 4), (3, 5), (4, 5), (5, 6)]
code = prufer_encode(6, tree_edges)
print("Encoded Prüfer code:", code)
print("Decoded edges:", sorted(tuple(sorted(e)) for e in prufer_decode(code)))

def glaisher_odd_to_distinct(parts):
    counts = Counter(parts)
    out = []
    for k, m in counts.items():
        bit = 0
        while (1 << bit) <= m:
            if m & (1 << bit):
                out.append(k * (1 << bit))
            bit += 1
    return sorted(out, reverse=True)

for odd_p in [[5], [3, 1, 1], [1, 1, 1, 1, 1]]:
    print(f"Glaisher {odd_p} -> {glaisher_odd_to_distinct(odd_p)}")
```

```output
Encoded Prüfer code: [4, 4, 5, 5]
Decoded edges: [(1, 4), (2, 4), (3, 5), (4, 5), (5, 6)]
Glaisher [5] -> [5]
Glaisher [3, 1, 1] -> [3, 2]
Glaisher [1, 1, 1, 1, 1] -> [4, 1]
```

## Common Traps

> [!TRAP]
> **Labeled Trees vs Unlabeled Tree Shapes**
> Cayley's formula counts **labeled** trees ($6^4 = 1296$ on $6$ vertices, treating vertex names `1..6` as distinct). If vertex labels are erased so only abstract shapes matter, there are only $6$ non-isomorphic unlabeled trees on $6$ vertices!
